# Workbench Studio — public edition, private Windows candidate

This edition has its own settings, artwork cache, build cache and history. It does not change a personal Studio installation. Launch `Workbench Studio.cmd`; the package includes its native SDL3/ImGui interface and Python runtime. Git for Windows must be available on PATH. Optional Advanced source builds also require PowerShell 7 (pwsh); the included supported versions do not. No installer or global configuration change is required.

Set BIOS files, their regions and an output folder in Settings. Then select or drop game images and matching SBI files together. One Game groups its selected discs; Multiple Games takes one image per single-disc game and one M3U playlist per multi-disc game. A playlist remains one game in its listed disc order. Select CUE rather than individual BIN tracks.

BUILD starts a fixed snapshot of the selection. Jobs run serially with one resolved core/UI pair for the entire batch. Completed cards are blue, failed cards red, active cards highlighted and queued cards neutral. A failed game does not stop later games; a shared source/toolchain error stops the batch. Cancel stops the active process tree and the remaining queue. Current game and Total time use a monotonic clock; final game and batch durations are retained in Studio history.

Successful games are delivered directly into the selected output folder, with no batch wrapper or numbering. Existing folders are preserved; a duplicate name gets a numeric suffix. Each delivered file is hash-checked. Build logs and receipts stay under `public-studio-data/history`. Compiler scratch uses a separate short persistent root; successful temporary payloads are removed. Failed work remains there for diagnosis. The output folder contains delivered games only.

Custom source builds copy the selected working files into a private snapshot. Snapshot files are writable so the selected core can stage BIOS and generated files; the original files and their read-only attributes remain unchanged.

Advanced accepts the established PSX core `PIN.json` and matching `UI.json`, including its actual launcher module and shared SDL contract. Selected records and source versions freeze once per batch. A preserved modern local-source pair completed a portable Ape Escape build, module compatibility check and a 600-frame recording/playback check. Arbitrary online Git refs remain unqualified. Existing-pin MGS and RE2 products passed their private startup checks, and Alex reported that both games work. These checks do not qualify whole-game or strict fleet replay behavior.

Advanced compiler choices are Fast build (`-O1`) and Optimized runtime (`-O3`), with a separate LTO toggle. The selected runtime LTO setting is applied explicitly and can increase link time. PGO is separate: opting in starts the game with hidden video and muted audio to collect a profile before rebuilding. Diagnostics requests a separate diagnostics product.

Startup checks are OFF by default in this edition. Turning them on requests the executable setup self-check, moved private starts and captured-overlay checks; these add several minutes and do not qualify gameplay. Source/media integrity and selected module/SDL/assets compatibility are always checked. Pin programme qualification is unchanged. Skip BIOS requests fast boot in the established pin route; that builder still requires a region-compatible BIOS file.

Opening Studio, changing Settings and selecting games do not fetch core, UI, source or toolchain packages. Build performs that work and may reuse this edition's existing cache. Artwork is the exception: selection can identify the disc, reuse local art, or fetch an optional cover from the existing player's PSX cover source. Missing/offline art never blocks Build. Branding, fonts and the artwork reader are bundled locally.

`assets/SOURCE.json`, `assets/NATIVE-SOURCE.json` and `PACKAGE-RECORD.json` record bundled inputs. Linux and the upstream source-only build route remain unqualified. File dialogs, drop behavior and the redesigned mapped UI still require Alex's hand check; hidden rendering alone does not prove those interactions.

The sharing package supplies sanitized supported core/UI version records under ersions. It downloads the public core commit after Build and expands the included checksummed launcher build-source export then. The launcher source revision is not available from the public remote; it is not fetched there. Its module, SDL and asset identities are checked exactly. The export excludes Git history, private records, documentation and test fixtures, and records its original source commit/tree plus the exported file hashes.

The native Build bridge uses %LOCALAPPDATA%\RPT\s for source/toolchain caches, %LOCALAPPDATA%\RPT\w for compiler scratch, and %LOCALAPPDATA%\RPT\compilers for persistent thin-game compilers. These roots are captured before child tools receive isolated appdata paths. Build creates payload caches; opening, settings and selection do not. Thin games depend on the persistent compiler store; portable games carry their compiler. The clean sharing package contains no private candidate cache/work overrides.
