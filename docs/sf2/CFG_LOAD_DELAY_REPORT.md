# PSXRecomp CFG load-delay defect — portability report

Date: 2026-08-02  
Fix commit: `663ac4a021c5630922ca58bb223e2df1f84a8830`

## Summary

PSXRecomp's captured-overlay CFG emitter made ordinary MIPS-I loads visible to
the immediately following instruction. Real PS1 hardware executes that
instruction with the destination register's old value and exposes the loaded
value afterward. The separate full-function emitter already preserved this
rule; the defect was specific to the CFG path used by captured overlays and
related dynamically discovered code.

The fix is generic and is not tied to SF2 data, addresses, or gameplay logic.
It currently covers `LB`, `LBU`, `LH`, `LHU`, and `LW` when the immediate
successor reads the load destination in the same safe basic-block context. The
loaded value is deferred through that successor; if the successor also writes
the destination, the successor's write wins.

## Minimal reproducer

The failure was isolated with this OpenBIOS kernel idiom:

```mips
lw    k0, 0x4c38(k0)
move  at, k0
sw    k0, ...
```

Correct MIPS-I behavior is:

1. `lw` schedules a new value for `k0`.
2. `move at,k0` reads the old `k0`.
3. The loaded value becomes visible in `k0` after `move`.

The old CFG emitter assigned the loaded value to `k0` immediately, so `at`
received the new pointer. In the observed case this corrupted the BIOS CD event
queue and eventually caused lost CD interrupts and a deterministic frontend
freeze. The visible symptom was far removed from the faulty instruction pair.

## Applicability

This is a framework-wide correctness issue, but it does not necessarily affect
every game.

A project is exposed when all of the following are true:

- it executes code generated by the affected CFG/captured-overlay emitter;
- that code contains an ordinary load immediately followed by an instruction
  that reads the loaded register; and
- correctness depends on the old register value being observed.

Games using only the static full-function emitter may already receive correct
load-delay behavior. Games whose overlay code has no dependent load-use idiom,
or where the old and new values are equivalent or unused, may show no symptom.
Because BIOS/kernel handlers and compiler-generated assembly commonly use such
patterns, the fix should be treated as broadly relevant even though only one
retail route has supplied end-to-end evidence so far.

The current patch is deliberately conservative around labels and control-flow
boundaries. It does not claim exhaustive handling of every PS1 load-delay case;
paired/unaligned loads such as `LWL`/`LWR`, dependencies spanning CFG
boundaries, and unusual delay-slot interactions should be audited separately.

## Upstreamable patch boundary

The portable change consists of:

- `recompiler/src/code_generator.cpp`
- the focused regression in `recompiler/tests/recompiler_patch_test.cpp`

SF2 devlogs and the diagnostic environment-variable additions in
`runtime/src/dirty_ram_interp.c` are not required by the semantic fix and should
not be included in a minimal upstream patch.

## Suggested validation in another project

1. Apply or cherry-pick the two-file recompiler change.
2. Rebuild the recompiler; do not reuse an executable carrying the old emitter.
3. Regenerate affected overlay C and rebuild the overlay cache under a new
   codegen hash. Do not reuse old generated C or DLLs.
4. Run the focused regression and the complete framework test suite.
5. Compare two clean processes at a deterministic checkpoint.
6. Measure native-overlay and interpreter dispatch tiers separately.
7. If the project previously froze, compare bounded device/interrupt counters
   before and after; do not infer correctness from rendering alone.

For a direct code-generation check, inspect a dependent load-use pair and
confirm that generated host code evaluates the successor against the old guest
register value before committing the deferred load result.

## Confidence

Confidence is high that the diagnosed CFG behavior violates MIPS-I semantics
and that the patch fixes the observed ordinary-load dependency class. Evidence
includes a minimized instruction pair, agreement with the existing
full-function emitter contract, a focused regression, a 38/38 framework suite,
and repeated clean retail frontend runs after regeneration.

Confidence is not yet sufficient to claim complete load-delay correctness for
all games or all MIPS-I instruction combinations. Cross-title testing is the
right next validation step.
